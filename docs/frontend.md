## 統合後の現行実装（P1ローカルモック）

REACTION-02：実グループの候補詳細に「行きたい！」「そこまで」の選択肢、現在の自分の反応、2種類の件数、明示的な取り消しを追加。
保存中は操作を無効化し、失敗を成功として表示しない。保存成功時は対象詳細を再取得し、他メンバーの変更はページ再読込で反映する。未適用・取得失敗を0件と表示せず、候補本文と再読込操作は維持する。
下部ナビから開くデモの選択肢・検索条件・反応の表示も同じ文言に揃える。保存形式とデモの挙動は変えない。ユーザーが実リアクションのDB適用成功（version `20261017153040`）と、保存・再読込後の保持・変更・件数の移動・取消の成功を報告した。画面幅・キーボード・別アカウントは未確認。

ITEM-02ではグループ詳細の「みんなの候補へ」から`/app/groups/[groupId]/items`へ進み、名前・種類・メモを実DBへ保存する画面を追加。
一覧は新しい順・20件ごとで、グループ名と共有先を表示する。詳細`/app/groups/[groupId]/items/[itemId]`は両IDと所属を照合する。
入力失敗では値を保持して対象欄へフォーカスし、保存失敗時は成功として遷移しない。未適用は準備中の案内とし、0件と区別する。
ユーザーが`create_items`の実DB適用成功（version `20261017112451`）と、実アカウントでの追加・詳細再読込・一覧復帰後も名前とメモが残ることを報告した。別アカウントの共有、画面幅・入力失敗時の保持・読み上げは未確認。下部ナビのP1モックは維持し、フッターでも区別する。

2026-10-17：`/app/groups`に実グループの作成・一覧、`/app/groups/[groupId]`に所属を確認した詳細を追加した。
グループの実DB適用と作成・再読込後の保持はユーザー確認済み。既存P1デモの候補・予定・思い出はこのグループには紐付けず、画面でも区別する。
ヘッダーからグループ管理へ進める。グループ管理画面では固定デモグループ名を表示しない。

GROUP-03では詳細に招待リンクの発行・コピー・無効化を追加。7日間有効で複数人が使える。`/app/groups/join`だけは未ログインでも開け、tokenを受領後にURLから除去して一時cookieへ移し、ログイン・登録後に参加先を確認して参加する。
追加migrationが未適用の場合もグループ詳細は表示し、招待欄は準備中とする。招待の実DB適用成功はユーザーが報告済み。実ユーザーの参加・コピー操作は未確認。

AUTH-05では登録失敗時に、送信先制限・メールや操作の回数上限・入力条件・登録停止・通信失敗をAuthコードから固定の日本語へ変換する。providerの生メッセージは表示せず、未知の失敗は共通案内にする。

`/app`には共通枠と「ホーム／行きたい／おでかけ／思い出」の4タブがある。
`/app/items`はタイトル検索語をURLの`q`、種類（場所／やりたいこと）を`kind`、
自分の反応（行きたい／あんまり／未反応）を`reaction`で保持し、
候補詳細への移動と一覧への戻りでも条件を引き継ぐ。
候補詳細では名前とメモをこのブラウザのモックへ保存できる。編集前の訪問先名は思い出の記録として維持する。
`/app/outings`は計画中と終了済みを件数付きで分け、各区分の空状態と詳細への導線を表示する。
おでかけ作成フォームでは日付未定・候補の選択数・保存後の詳細への移動を明示する。
`/app/memories`は思い出の件数・計画日・訪問先を表示し、記録がない場合も詳細へ進める。
思い出詳細ではタイトルとメモをこのブラウザのモックへ保存できる。訪問先の記録は編集対象に含めない。
思い出詳細は一冊の本として、表紙・目次・訪問先ごとの章・あとがきを前後にめくれる。現行の章名は訪問先の保存済み名称を使う。
候補の追加・反応、計画作成、明示的な訪問記録、終了、思い出表示までの画面がある。
業務データは[モックの契約](../lib/kokoiko/contracts.ts)と
[ローカルリポジトリ](../lib/kokoiko/mock-repository.ts)に沿い、同じブラウザの`localStorage`へ保存する。
実DB・業務API・他ユーザーとの共有・写真の保存は未接続。グループ名は静的なデモ表示で、切替はできない。

`/`はP1のホーム`/app`へ転送する。`/protected`はSupabaseスターターの別ルートとして残る。
2026-10-17のAUTH-03では`/auth/*`を日本語化し、未設定時の送信抑止・デモ導線、登録・再設定メールのcallback、
アプリのログアウト導線を追加する。ログイン後は`/app`または`next`にあるアプリ内画面へ進み、外部URLとAuthへのループは拒否する。
実Authは[開発環境の設定](auth-setup.md)後に検証する。ログイン後も業務データは共有されない。
Auth proxyは業務モックとは別に動作し、Supabase環境変数が設定された環境では未認証の`/app`を
`/auth/login`へ転送する。環境変数が未設定ならその認証確認を飛ばす。
ビルドとHTTP応答に加え、360／390／1280pxの表示幅、候補から思い出までの操作、
再読込後の保持、検索からの復帰、スキップリンクへのTab移動を確認した。

## UI変更で扱う品質

N-01〜N-03は要件書の基準案。タスクの採用済みDoneを確認して適用する。
旧UIルールのモバイル優先・操作性・画像フォールバックも維持する。

- まず390px前後で成立させ、360px・390px・PC幅で検証する。
- ナビと最後のカード／主要CTAの重なり、横はみ出し、スクロールを確認する。
- タップ領域、文字量、余白、写真比率、CTA・カード階層を揃える。
- 読込中、保存中、データ0件、検索0件、取得失敗、保存成功を区別する。
- 送信中は二重操作を抑止し、失敗時に成功表示せず入力を可能な範囲で保持する。
- 空状態から追加・条件解除へ進める。画像なし・詳細削除済みの表示も設計する。
- ラベル・操作名・フォーカスを付け、色だけで状態を表現しない。
- 参考画像のピクセルコピーより、操作性・保守性・アクセシビリティを優先する。

実際の操作確認手順は[verification](verification.md)。ホームのQ-08、フォームのQ-05など、
対象画面の未決定事項を[decisions](decisions.md)で確認してから実装する。

## UI-01：共通枠のルート・導線案（当時の案、P1暫定ルートは採用済み）

2026-10-03に現行PNG5枚を目視し、現行コードの`/`、`/protected`、`/auth/*`と照合した案。
この節の作成時点では画面実装やURLの採用決定ではなかった。元フォルダから`frontend.md`と現行PNG5枚だけを
UI worktreeへ引き継いだ。旧`kokoiko-dev-starter/docs/design/`の18枚は比較・移植していない。

### 画面と入口

| 画面・入口 | URL案 | 根拠と扱い |
|---|---|---|
| アプリのホーム | `/app` | 現行ホーム画像。スターターの`/`をUI-02で上書きしない |
| 行きたい一覧 | `/app/items` | 現行一覧画像。場所／やりたいことは同じ一覧の種別切替案 |
| 候補詳細 | `/app/items/[itemId]` | 現行詳細画像。カードから開き、戻ると一覧条件を保つことを目標にする |
| おでかけ一覧 | `/app/outings` | 下部ナビの入口。独立画像は現行5枚にない |
| おでかけ計画 | `/app/outings/[outingId]` | 現行計画画像。候補詳細の「おでかけに追加」からの経路は別タスクで設計 |
| 思い出一覧 | `/app/memories` | 下部ナビの入口。独立画像は現行5枚にない |
| 思い出詳細 | `/app/memories/[memoryId]` | 現行思い出画像。一覧から開く |

`/app`配下を共通アプリ枠にまとめる案。下部ナビの4項目「ホーム／行きたい／おでかけ／思い出」は
全5画像で一致し、上表の4つの一覧入口へ移動する。詳細では所属する項目を現在位置として示す。
タブの代わりに候補追加・地図・カレンダーを並べない。これらは一覧・計画からの個別入口を
対象タスクで決める。未実装の入口を押せるダミーボタンとして置かない。

ヘッダーには現在のグループ名を明示する。画像にあるグループ切替は、選択先のデータ・入力先を
同時に切り替える契約ができるまで静的な表示にとどめ、開くふりをする操作にはしない。
グループをURLで識別するか、選択状態で保持するかはcoreの画面・データ契約と合わせる。
候補詳細などのIDを別グループで開いた場合の扱いは、実データ接続前にF-02とN-04で決める。

既存`/auth/*`は認証用、`/protected`はスターターの検証画面として別に扱う。
既存ログインは成功時に`/protected`へ遷移するため、`/app`への接続は認証タスクで変更する。
現行proxyは環境変数が設定済みなら未認証の`/app`を`/auth/login`へ転送し、
未設定ならチェックを飛ばす。UI-02のモック操作確認条件をこの挙動に合わせて明記する。

### UI-02の提案範囲とモック境界

UI-02では`/app`配下の共通レイアウト、4項目の下部ナビ、現在位置、グループ名の表示、
各ナビ先の最小の説明画面だけを作る案。最初の画面から4つの入口へ移動し、
戻る操作ができ、360px・390px・PC幅で本文と固定ナビが重ならないことを確認する。
キーボードで各リンクへ移動でき、フォーカスとリンク名が分かることも確認する。

最小画面の文言とグループ名は明示した仮データで、ユーザー間の共有・保存・検索はできない。
候補カード、検索、追加、反応、コメント、計画保存、訪問記録、思い出編集、地図API、
写真アップロードはUI-02の対象外。現行画像のCTAは後続の対象タスクで遷移先と動作を決める。
UI-03以降のカード用データはcoreの共通型に合わせ、画面独自の形式を増やさない。

確認が必要な点：`/app`を正式入口にするか、後で`/`へ移すか。グループ選択状態の保持場所。
ログイン後の行き先とP1モックを試す認証条件。Q-08の「みんな」、Q-05の入力規則、
Q-09の計画モード切替規則はそれぞれの画面に着手する時点で決める。
