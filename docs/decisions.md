# 判断と未決定事項

作成日：2026-10-03。要件の正本は[要件定義書](kokoiko-requirements.md)。
「採用済み」は人間の明示した判断に限る。コードの存在・AIの提案・資料の閲覧を採用根拠にしない。
変更時はID・日付・状態・背景・採用内容・影響する要件ID・判断根拠を残す。
状態は提案／要確認／採用済み／却下／置換済み。未採用案を採用済みに書き換えない。

## 採用済みの文書運用

### D-005：ルートからP1画面へ進む

- 日付：2026-10-05
- 状態：採用済み（P1の入口）
- 背景：統合後も`/`にNext.jsスターター画面が残り、`npm run dev`の初期URLでここいこのUIが見えなかった。
- 採用内容：`next.config.ts`で`/`を`/app`へ一時転送する。認証環境が設定された場合、未認証の`/app`は既存proxyによりログインへ進む。
  ここいこの業務データは引き続きローカルモックで、実Auth接続の完成を意味しない。
- 影響する要件ID：N-01、N-09。
- 判断根拠：2026-10-05のユーザー指摘「mainでnpm run devしてもnextの画面しか見えない」。
- 関連タスク：UI-ROOT-01。

### D-004：検証後のmainへの統合

- 日付：2026-10-05
- 状態：採用済み（開発運用）
- 背景：P1統合のレビューとローカル検証を終えた後、開発を継続する指示を受けた。
- 採用内容：対象差分の検証とレビューが成功し、既存の作業ツリーを保護できる場合は、
  Agentが追加の確認を待たずに`main`へマージできる。失敗・未確認を成功と扱わず、結果を報告する。
  push・deploy・実サービスの変更はこの指示に含めない。
- 影響する要件ID：N-09、N-10。
- 判断根拠：2026-10-05のユーザー指示「検証成功しているなら私に聞かずにマージしてください」。
- 関連タスク：VERIFY-04、CI-02。

- 状態：採用済み（運用）
