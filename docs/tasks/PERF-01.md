# PERF-01：保存・投稿後の表示待ちを減らす

作成日：2026-10-18。状態：実装・ローカル検証・自己レビュー完了。CI・統合はこの変更のPRを正本とする。実際の体感時間と改善率は未計測。担当：本Agent単独。
branch：`perf/post-save-rendering`。基準：`1a90b20`。F-02/04/05/06、N-02/04/07/10。

## 背景・Goal

ユーザーが候補編集・絞り込み・コメント・グループ名変更・2タブの上書き防止をすべて成功と報告した。その上で表示の遅さを指摘し、主なタイミングは「保存・投稿した直後」と回答した。
読み取り調査で、候補詳細はグループ取得→候補取得→反応取得、その後にコメント部品を描画する構造だった。本文と反応・コメントの待機境界が分離されておらず、グループ詳細も招待取得を待って本文を返していた。
実際の遅延の主因・所要時間は未計測で、開発モードだけの問題とは断定しない。独立した通信の直列待ちと、補助部分の読み込みが本文を待たせる構造を先に改善する。

## 範囲・Done

- 認証確認後の候補詳細のグループ/候補、一覧のグループ/候補一覧を並列取得する。どちらも既存RLSと明示的なグループ条件を維持する。
- 詳細の反応・コメントをそれぞれSuspense内のServer Componentに分け、本文・編集フォームを先に表示可能にする。補助部分のエラーと再試行をその部分に閉じる。
- グループ詳細の招待を独立した待機境界へ分け、名前・候補入口・名前変更フォームを招待取得で待たせない。
- 保存Actionの認証・所属確認・競合検知・冪等性・再取得対象は変更しない。SQL・DB・キャッシュ方式・認証構成・外部API・依存追加は対象外。
- 既存の入力・RLS・取得・Action検証、lint・型・buildと必要な描画構造検証、自己レビュー・最新CIを確認する。
- 実Authの保存後体感時間・本番ビルドでのブラウザ測定・DB所要時間の切り分けは未実施。改善率を実測済みとして報告しない。

公式根拠：[Next.jsの並列取得とStreaming](https://nextjs.org/docs/app/getting-started/fetching-data)。開発/本番モードは[CLI](https://nextjs.org/docs/app/api-reference/cli/next)を参照する。
開始前のREADME・旧資料削除・pnpmファイルを保護する。共通文書の編集は本Agentのみ。
