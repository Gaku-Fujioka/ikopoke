# AUTH-05：新規登録エラーの切り分け

作成・更新日：2026-10-17。状態：原因確認済み、表示修正のローカル検証済み、CI・統合待ち。F-01、N-02/03/05/10。branch `fix/signup-error-feedback`、本Agent単独。

## 再現・Goal

GROUP-03の実操作確認で、ユーザーが招待リンクから別アカウントを作ろうとすると登録に失敗した。
画像の表示は既存の一律エラーで、Supabaseのエラーコードを捨てており原因を判別できない。
既知の登録エラーを固定の日本語へ変換し、メール送信制限・回数上限・入力条件・登録停止・通信失敗を案内する。
ユーザーが接続先チャットのAuthログ調査結果として`over_email_send_rate_limit`・HTTP429を報告した。今回の直接原因は確認メールの送信回数上限であり、宛先許可のエラーとは区別する。

## 範囲・制約・Done

- `lib/auth/`のエラー変換、`components/sign-up-form.tsx`、回帰テスト・CIと進捗記録。
- providerの生メッセージ・メールアドレス・パスワード・tokenを画面やログへ出さない。未知の失敗は安全な共通メッセージを維持する。
- 登録成功後の招待復帰とメール確認は維持し、Auth設定・メール確認の要否・DB・依存は変更しない。
- 既知コード・未知コード・非標準の例外と情報漏えい防止のテストを実施する。lint・型・build・関連テスト・最新CIを確認し、D-009に従い統合する。
- 開始前のREADME編集・旧スターター削除・pnpmファイル・環境変数を保護する。独立レビューは未実施として扱う。

## 根拠・未解決

Supabase公式の[Authエラー](https://supabase.com/docs/guides/auth/debugging/error-codes)と[標準メールの制限](https://supabase.com/docs/guides/auth/auth-smtp)を確認。
標準SMTPではプロジェクトのチーム外の送信先が拒否され、回数上限もある。これは今回の原因を確定した証拠ではない。
実環境のエラーコードはユーザー報告で確認済み。Agentは公開Auth設定HTTP200、メール登録有効・登録停止なし・メール確認ありを値を表示せず確認した。
SMTP設定の詳細と回数上限の回復時刻は未確認。ユーザーは「外部メール送信サービスを設定する」を選択した。外部SMTPの準備はAUTH-06で進め、手順はチャットで案内する。
