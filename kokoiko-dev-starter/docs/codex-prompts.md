# Codexへの依頼テンプレート

Codexには「全部作って」ではなく、毎回小さく明確に依頼する。

## 1. 初回のリポジトリ確認

```text
このリポジトリの開発を手伝ってください。
最初に AGENTS.md、TASKS.md、docs/product-spec.md、docs/architecture.md を読んでください。
まだコードは変更しないでください。
現在のプロジェクト構成を確認し、最初に取り組むべき作業と理由を簡潔に説明してください。
```

## 2. UIを1画面作る

```text
ホーム画面を実装してください。

要件:
- docs/design/01-home.png をUI参考にする
- docs/product-spec.md に従う
- 今回はモックデータのみ
- Supabase接続はまだ行わない
- モバイルファースト
- 既存の共通コンポーネントがあれば再利用する
- このタスクと関係ない画面は変更しない

完了後:
- 変更ファイル
- 実装内容
- 実行したlint/build等
- 私がブラウザで確認すべき操作
を報告してください。
```

## 3. 修正する

```text
現在のホーム画面について、下部ナビゲーションがコンテンツに重なります。
原因を調査して修正してください。

条件:
- 関係ないデザイン変更はしない
- 修正範囲を最小限にする
- モバイル幅で再現確認する
- 修正後にlint/buildを実行する
```

## 4. Supabaseへ接続する

```text
現在モックデータで表示している行きたい一覧をSupabaseの実データへ切り替えたいです。

最初に関連コードと docs/data-model.md を確認してください。
いきなり実装せず、必要なテーブル・migration・RLS・変更ファイルを整理してから実装してください。

条件:
- RLSを有効にする
- 秘密鍵をClient Componentへ渡さない
- migrationを残す
- Empty / Loading / Error状態を考慮する
```

## 5. コードレビューだけ頼む

```text
現在のブランチとmainのdiffをレビューしてください。
コードはまだ変更しないでください。

優先順位:
1. バグ
2. セキュリティ
3. データ損失の可能性
4. Next.js/Supabaseの不適切な使い方
5. UIの回帰
6. 保守性

問題ごとに、重要度・該当ファイル・理由・推奨修正を示してください。
問題がなければその旨を明示してください。
```

## 6. commit前の最終確認

```text
このブランチをcommitする前の最終確認をしてください。
未commitのdiffを確認し、lint/typecheck/build/関連テストを実行してください。

以下を報告してください:
- この変更が何をするものか
- 意図しない変更が混ざっていないか
- テスト結果
- commitしてよい状態か
- 残っているリスク
```

## 良い依頼の形

「対象 + 今回やること + やらないこと + 参考資料 + 完了条件」を書く。

悪い例：

`ここいこ全部作って`

良い例：

`行きたい一覧のモックUIだけ作る。DB接続はしない。02-wishlist-list.pngを参考にし、カードから詳細へ遷移できれば完了。`
